## 参数与默认值

所有默认值都可配置，不是证件照的固定规则。

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `--target-size` | `240x320` | 输出宽高像素 |
| `--background-rgb` | `66,142,217` | 合成前的纯色 RGB |
| `--min-bytes` | `15360` | JPEG 文件最小字节数 |
| `--max-bytes` | `70000` | JPEG 文件最大字节数 |
| `--background-tolerance` | `12` | 解码后安全背景与目标 RGB 的欧氏色差上限 |
| `--modnet-short-edge` | `512` | 实际送入 MODNet 的短边；必须为 32 的倍数 |
| `--composition-face-box` | 按目标尺寸缩放 `63,53,120,120` | 目标图中的 `x,y,w,h` 脸框参考 |
| `--expected-count` | `0` | `0` 不检查数量；正数强制对账 |
| `--limit` | `0` | `0` 处理全部；样片使用 `1` |

保持短边 `512` 作为稳健默认。更高分辨率不一定更准；真实批次中 `768/1024` 曾把衣物内部误判为背景并产生孔洞。若改变该值，先做样片并重点检查衣物内部 Alpha。

脚本只扫描源目录顶层的 `.jpg`/`.jpeg`，不递归。相机生成、扩展名为 JPG 但由 Pillow 识别为 MPO 的文件会读取首帧、应用 EXIF 方向并转为 RGB。

## 构图覆盖文件

默认使用本地 OpenCV Haar 检测正脸，再把源脸框映射到目标脸框。检测失败时应停止，不得静默中心裁切。使用 JSON 覆盖单张异常：

```json
{
  "example.jpg": {
    "source_face_box": [100, 120, 240, 240],
    "target_face_box": [63, 53, 120, 120]
  },
  "approved-crop.jpg": {
    "crop_box": [20, 10, 920, 1210]
  }
}
```

- `source_face_box` 使用源图 `x,y,w,h`。
- `target_face_box` 使用输出图 `x,y,w,h`，可按文件覆盖全局构图。
- `crop_box` 使用源图 `x0,y0,x1,y1`，必须在图内且宽高比与目标尺寸一致。
- `crop_box` 最好同时给出框内的 `source_face_box`，这样脚本能计算实际目标脸框；缺少时报告会标记构图未经验证，QA 默认要求人工复核。
- 文件键只能是文件名，不得带目录。不要把任务专属覆盖文件复制进 Skill。

## 连续 Alpha 与背景替换

按以下不变量验收处理逻辑：

1. 用 MODNet ONNX 和 `CPUExecutionProvider` 做完全本地推理。
2. 把模型输出以线性插值还原到裁切分辨率，并保留 `[0,1]` 连续 Alpha。
3. 仅把数值端点 `<=0.01` 吸附为 0、`>=0.995` 吸附为 1；不得对人物做硬阈值、腐蚀或主连通域删除。
4. 从确定背景像素估计原背景，再用预乘色换底公式替换为目标纯色。确定背景不足时硬失败。
5. 先在未压缩 RGB 中把确定背景写成精确目标 RGB，再编码 JPEG。

JPEG 是有损格式，因此重新解码后不能要求每个背景像素逐字节等于目标 RGB。规格 QA 应在重新计算的安全背景区域统计色差，默认以 RGB 欧氏距离 `12` 做门禁，并同时记录 p99 与超限比例。

## JPEG 体积策略

依次对 4:4:4、4:2:2、4:2:0 搜索不超过上限的最高 JPEG quality，并优先更高 quality、再优先更少色度抽样。始终使用确定性的非 progressive、`optimize=True` 编码并剥离源元数据。

若最佳编码低于下限，默认 `jpeg-comment` 策略插入标准 JPEG COM 段，使文件达到下限；这不改变解码像素，报告会记录 `padding_bytes`。若下游系统拒绝带 COM 段的 JPEG，改用 `--padding-policy fail`，无法自然达到下限时硬失败。若最低 quality 仍超过上限，也必须失败，不能静默违反规格。

## 规格门禁与视觉分诊

处理阶段在 staging 目录生成所有照片。任一照片失败时停止并删除 staging；全部照片通过后才把目录提交为正式输出。脚本在处理前后核对源文件 SHA-256，且拒绝任何已存在或与源目录重叠的输出目录。

确定性规格门禁包括：

- 输入、输出和批报告的文件名集合一致；
- 输出可解码为 RGB JPEG；
- 宽高、字节上下限和 SHA-256 符合报告；
- 模型哈希与处理阶段一致；
- 安全背景区域的目标 RGB 色差通过；
- 独立 MODNet 前向的 Alpha 均值与批处理记录一致。

视觉分诊包括：

- 橙色：原图中靠近人物的细节在 Alpha 中接近透明，可能漏掉细发、马尾或颈侧长发；
- 红色：脸部以下出现不与画面边界连通的透明区域，可能是衣物误抠洞；
- 品红色：Alpha 人物外缘紧邻区域仍有非目标背景颜色，可能残留或 halo；
- cohort 构图离群：前景占比或头顶位置相对同批明显异常。
- 单张构图留白：默认头顶留白低于画面高度 `1.5%` 或高于 `20%` 时标记；可用 `--head-top-min-ratio`、`--head-top-max-ratio` 按规范调整。

规格失败返回 `1`。视觉标记默认令 QA 返回 `2` 和 `review_required`；只有在明确人工接受后才用 `--allow-visual-flags` 返回 `0`。报告状态包括 `pass`、`failed`、`review_required`、`accepted_with_visual_flags`。

联系表使用无损 PNG，并以 1:1 显示 240×320 目标图。为避免在联系表标题重复姓名式文件名，每格使用 `contact_index`；在 `qa_report.json` 的逐文件记录中按该索引定位原文件名、页码和格位。

## 人工验收清单

逐张放大联系表并检查：

- 细碎刘海、发梢、鬓角是否保留连续半透明过渡；
- 马尾、披肩长发和颈侧长发是否被当成背景；
- 眼镜框、耳饰、发夹等细结构是否缺失；
- 领口、肩部、深色或蓝色衣物内部是否出现孔洞；
- 人物边缘是否有旧底色、蓝边、白边或锯齿；
- 远背景和人物近边缘是否为均匀目标色；
- 头顶留白、脸部大小、水平居中和肩部裁切是否符合目标参考；
- 文件名、数量、尺寸、格式和体积是否与需求一致。

## 隐私与产物保留

脚本不包含网络客户端，也不会主动上传或调用远程服务，但无法可靠识别 OneDrive 等同步目录、映射盘或操作系统挂载的网络存储。把源图、输出、报告、模型和 QA 目录放在调用方确认的本地非同步位置。

批报告为逐文件核验保留文件名、SHA-256、裁切框和脸框；QA 联系表包含对齐原图、Alpha、成片和风险遮罩。报告不记录绝对目录，但这些文件仍属于敏感派生数据。不得复制进 Skill、代码库或公开共享位置；完成任务后按用户的数据保留要求删除或归档。

## 已知限制

- Haar 正脸检测对侧脸、遮挡、强光和极小脸不稳定；使用人工批准的覆盖框。
- 自动漏发检测会被源背景纹理干扰，也可能漏掉与源背景颜色相近的浅色头发。
- 合法的发丝/颈部空隙可能被标记为内部孔洞；自动标记只用于排序和复核。
- cohort 离群无法发现整批共同的系统性构图错误，小样本也不会运行 cohort 判定。
- 本 Skill 不判断特定国家、考试或平台的合规规则；先取得对方的明确尺寸、背景、体积和构图规范。
